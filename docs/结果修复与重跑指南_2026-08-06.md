# 八模型结果修复与重跑指南

## 1. 本次代码修复了什么

- 验证器先检查正式 `geometry_robustness_status`，不再把 `NOT_SUPPORTED` 模型误写成 English hub。
- 所有 paper_v1 manifest 与轨迹 JSON 使用严格 JSON；NaN/Infinity 会写成 `null`。
- 增加八模型统一比较套件，但明确标记为两个预设批次的事后合并，不能伪装成预注册八模型清单。
- 增加本地checkpoint逐文件SHA-256审计，可在不加载模型、不使用GPU的情况下补齐权重可追溯性。
- probe默认作为效应量诊断，不用20次置换产生分辨率不足的p值；少于199次时验证状态明确为 `DESCRIPTIVE_EFFECT_ONLY`。
- 增加三个代表模型的独立seed复现套件。

## 2. 立即修复现有八模型结果（无GPU）

在项目根目录、`langhub` conda环境中运行：

```bash
python src/repair_paper_outputs.py \
  --suite configs/model_suite_week1_all_eight_random200.json
```

该命令只读取已有：

```text
outputs_week1/<model>/hidden/sentence_layer_mean_pool.npy
outputs_week1/<model>/hidden/metadata.csv
outputs_week1/<model>/extraction_manifest.json
```

它会重新计算受NaN影响的范数/轨迹摘要，重新生成八份论文验证摘要，执行严格JSON检查，并生成统一八模型比较。不会导入Transformers，不会加载权重，不会重新提取hidden state。

如果希望所有离线指标都从已有hidden state完整重算，可运行：

```bash
python src/repair_paper_outputs.py \
  --suite configs/model_suite_week1_all_eight_random200.json \
  --rerun-all-offline
```

完整离线重算仍不需要GPU，但probe、bootstrap、置换和PCA会占用CPU。当前正式配置将probe限定为效应量诊断，避免无必要的数万次逻辑回归拟合。

## 3. 补齐权重身份（无GPU，但需要权重目录）

```bash
export LHT_MODEL_ROOT=/root/autodl-tmp/models
python src/audit_checkpoint_identity.py \
  --suite configs/model_suite_week1_all_eight_random200.json
```

脚本会完整读取权重文件并计算SHA-256，因此会产生较高磁盘读取，但不使用GPU，也不改变权重。结果写入每个模型输出目录的 `checkpoint_identity.json`，并把聚合hash写回 `extraction_manifest.json`。原仓库revision存在时仍保留revision；不存在时使用内容hash提供可复现身份，不伪造commit SHA。

## 4. 独立seed三模型复现（需要GPU重新提取）

```bash
python src/run_formal_suite.py \
  --suite configs/model_suite_replication_three_seed20260806.json \
  --resume
```

新seed改变了200个semantic IDs，旧hidden state不能复用。模型选择已经冻结为：XGLM-1.7B（强原始hub）、Mistral-7B（负对照）、Aya-23-8B（指令微调扩展）。这一阶段需要GPU完成新的模型前向；前向完成后的所有指标计算可切换到无卡实例继续。

## 5. 哪些任务需要GPU

| 操作 | 是否重新提取hidden | 是否需要GPU |
| --- | --- | --- |
| 修复claim、重新验证、八模型汇总 | 否 | 否 |
| 重算相似度、K、范数、轨迹、AlignmentGain | 否 | 否 |
| probe、bootstrap、置换、绘图 | 否 | 否，主要使用CPU |
| checkpoint SHA-256审计 | 否 | 否，主要使用磁盘I/O |
| 新seed/FLORES full-dev复现 | 是 | 建议GPU |
| 新增模型 | 是 | 需要GPU |
| 生成行为评估 | 不复用句向量hidden | 需要加载模型，建议GPU |
| 激活hook与方向干预 | 需要新的生成前向 | 需要GPU |

行为和激活干预是新增实验，不属于对现有结果的修复。当前代码继续把两者标为 `NOT_RUN`，避免在任务集、语言识别器、held-out划分和hook完整性测试尚未冻结时产生虚假的因果结论。
